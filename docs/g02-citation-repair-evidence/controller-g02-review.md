# G02 引用修补：主控独立设计审查与验收条件

日期：2026-09-26。本文件是对当前代码和既有真实输出的只读设计审查，不是修补完成或模型质量通过声明。范围限于 `context_brief` 的分项自身引用、摘要继承与有用内容保留；不扩大到 Agent、所有写作工具或通用语义验证器。

本次读取：`backend/app/engine.py` 的 `WritingAnalysisEngine`，`backend/app/v2_database.py` 的分析输入构建，以及 `evaluation/current_flash_v2/independent-round2/semantic-review.md`。没有运行 Provider、读取数据库/凭据、改变产品或既有评测证据。

## 结论

修复要同时解决两个独立缺口：**引用展示与事实覆盖不一致**，以及**已解析的引用 ID 被误当成逐项语义支持**。加长草稿 claim 只能处理第一类的部分案例；把结果统一标为 partial、清空全部分项或增加提示词不能单独构成修复。

建议以可核对的正文摘录、结构化 Memory 事实和清晰层级为基础提供有用结果。任意改写无法由字符相似度、关键词、全部引用 ID 的并集或另一个模型的单次打分自动证明。对无法验证的模型措辞，可以保留语义正确的来源摘录、缩减为引用真正支持的事实，或只移除问题分项；不必为了保留原措辞而宣称已经验证，也不能因此清空其余正确内容。

## 现有因果链

1. `v2_database.py:2971–2981` 按句号等拆句，每个 claim 只供给前 240 字；`2979` 记录完整句和供给范围。`2883–2893、2996` 另行生成最多 1200 字的 draft excerpt。因此模型可在 excerpt 中看到句尾，但它唯一可选的该句 claim 仍没有句尾。需在**同一已保存 revision 的可引用结构**内解决此不一致，不能让引用标签暗示包含不存在的尾部。
2. `engine.py:457–478` 的 `_clean_source` 验证 ID、类型并填入 excerpt。Memory 引用是 subject/predicate 标签与 value；`source_span_id` 的存在不意味着 Memory 引用覆盖源段所有额外事实。SourceSpan 的 body 本身也已经是有界摘录，不能退回完整数据库原文补推理后假称模型已经见过。
3. `engine.py:502–509` 只识别“另一条完整 draft claim 原文被直接复制，但引用错 ID”。它没有验证非逐字改写、Memory/SourceSpan 分项的全部事实、否定或时间。仅把 substring 改成相似度门槛会引入同类漏洞。
4. `engine.py:532–548` 从已保留 items 组装摘要，能够避免直接采用无依据的模型摘要，但当 item 本身仍有缺口时，会把缺口原样带入最终摘要。摘要的长度和三来源上限也不能导致文本保留而相应来源被丢弃。

这些是读取时的位置；实施后验收应以实际 diff 为准。

## 必须关闭的两个真实反例

来自 V2 `cases/02-g02-long-sentence.json`，旧文件必须保留。

**A：草稿句尾。** 299 字实际 draft excerpt 含“最后把银钥匙交给陈澈并得知弟弟还活着”，240 字 draft claim 只有反复走廊描述。最终 item 1 和摘要仍陈述句尾，唯一草稿引用缺少该事实。

验收允许两种可解释结果：让句尾进入真实、正确绑定且显示的引用，并保留该事实；或将该分项缩减成现有引用确实支持的正文内容，并明确剩余范围。对这一仅 299 字且在已选正文内的固定样本，优先修复引用可达性并保留句尾信息；不能只增加“已截断”文案而继续无引用地陈述句尾。

**B：额外坐标能力。** 最终 item 2 同时写“温岚看得懂潮表上的坐标”和“不知道廊桥钥匙的含义”，但只引 `does_not_know` Memory。真正支持坐标能力的 SourceSpan 已在实际输入中，并由 item 12 正确引用。

验收允许：在该 item 自身正确引用这段实际选中 SourceSpan，或只保留 Memory 支持的知识边界，另以有对应来源的分项保留坐标能力。不能因为另一条引用了该 span、Memory 恰好有 source_span_id 或全文出现过相同词，就把 item 2 判成支持完整。

## 关键约束

- 判断单位是**一条 item 的每个事实分句和该 item 自身来源**；summary 使用自己的来源。多个来源可共同支持多事实，但每一分句均应有可核对的支持关系。
- 引用来自实际绑定输入的白名单，并保留 source type、ID、draft/source revision 与对应 excerpt。相同文本出现在不同时间、人物、章节或版本时，不能仅凭文本相似自动换 ID。
- 摘录不是任意 substring。保留否定、时间、主语、归属及引述框架；“不知道密码”含“知道密码”这个字符串，并不支持肯定句。“他说‘我知道密码’，这是谎言”不能被抽成叙述者确认的“他知道密码”。
- Memory 必须保留 subject + predicate + value 的关系。只拷贝 value、漏掉 `does_not_know` 这样的否定谓词，会把事实改变。planned、confirmed、written 不得互相升级。
- 完整原文位于请求中别处，不代表当前来源已经支持；显示 `partial` 或来源可跳转也不弥补这条具体事实缺口。
- 有效的自由改写可以保留，但若实现无法可靠证明，应改为语义忠实、有明确自身引用的表达；验收看最终是否安全且有用，不强制保留模型原句，也不将所有改写一律删除视为合格。
- 对超长句和有界来源采用明确、可重现的范围处理，不无限扩张提示词。新增块须能回溯原句、偏移和 revision，不能跨省略号拼出原文不存在的连续语义。不要通过移除否定/条件后半句，制造看似完整的摘录。

## 最小正负控制矩阵

以下是修复验收材料，不是新增真实模型准确率的分母。可先用隔离合成输入和固定 Provider 输出做产品回归，再由主控独立改变名字、时间和来源排列构造反例。

| 编号 | 输入 / 模型输出场景 | 必要结果 |
|---|---|---|
| P01 | 正常三句草稿，逐条引用对应完整 claim | 三个事实仍有可用、有自身支持的输出；不能降为全空或无内容的拒绝 |
| P02 | 299 字真实长句，关键信息在第 240 字以后 | 尾部引用可达且显示完整支持，或有明确有限降级；原 V2 item/summary 漏洞不得原样保留 |
| P03 | 一个 item 含 A、B 两事实，并自身引用同时支持 A、B 的源段 / 两条来源 | 正确事实应保留；多事实不能被一律拒绝 |
| P04 | 坐标能力 + 知识未知，同时自身引用正确 SourceSpan 和 Memory | 两事实保留且层级准确；与只有 Memory 的负控形成差异 |
| P05 | 否定、直到某时才知、回忆 / 明确引述，输出完整忠实原文或等义表达 | 保留限定后的有效内容，不能把含否定 / 时间词本身当作需删除的理由 |
| P06 | 两个同文完整 claim，分别同一主体/语义，引用其中合法一条或两条 | 不因重复文本误判错配；覆盖条数与实际重复情况分别披露 |
| P07 | 空草稿，但有有效已确认 Memory 与相关源文 | 仍提供这些有支持的背景；草稿状态为 empty，不伪称有当前草稿内容 |
| N01 | 三项 A/B/C 的引用轮换为 B/C/A，全局 ID 集合仍完整 | 每个错配不能以全局覆盖通过；保留/重建真正有用的正确事实并标出调整 |
| N02 | 与 N01 相同，但将文本作同义改写，避开完整原句 substring | 不能因没有命中旧直接复制检测而自动 supported |
| N03 | item 陈述 A+B，只引支持 A 的 Memory；B 的源文只在另一 item | B 不得在该 item 内作为已支持事实保留；不能借用另一 item 的引用 |
| N04 | 源文“温岚尚不知道密码”，输出“温岚知道密码” | 即便词面高度相似/substring 存在，也不保留相反事实 |
| N05 | 源文“18 点未知，直到 19 点才获知”，输出“18 点已知” | 不接受错误时间；正确“19 点获知”应作为正控保留 |
| N06 | 源文“乔霁把钥匙交给沈砚”，输出换主客体；或不同人物只有同名词共现 | 不以词汇集合相同接受关系翻转；不得补造人物身份链接 |
| N07 | 源文明确某人说谎 / 回忆昨日，输出当成当前叙述者确认 | 保留原框架或缩减为安全摘录，不能去掉归属和时间 |
| N08 | 长句尾部含“不”“只是传闻”等改变前半句含义；范围在限定词前截断 | 不把被截断前半句升级为完整确认事实；范围和未覆盖部分可见 |
| N09 | 所引 ID 不存在、跨项目、错 revision；或同文但另一时段来源 | 拒绝非法绑定，不能用全库搜索或相似文本悄悄补接 |
| N10 | 原始模型摘要混入未被保留 item 支持的背景；或摘要三引用上限会漏掉第四来源 | 最终摘要从安全内容构建，文本和来源同步取舍，不残留无来源分句 |
| N11 | 全部模型措辞都无根据，但输入有两条清晰可靠事实 | 应输出有引用的可靠事实或明确局部结果；不能返回 supported + 原错误文本，也不能以永久全清空作为修复 |

P02 的极端超长扩展可明确限于保留部分，但正常可容纳输入不应一律牺牲尾部。P06 的同文可替代只适用于实际语义与绑定等价，不给 N09 的不同版本/时间开后门。

## 主控通过条件

1. **两个真实缺口闭环。** 对 A/B 的最终 item 和 summary 逐条人工核对自身显示引用；`partial` 标签单独不算通过。已存在的正确 V2 items 不能因修补普遍丢失。
2. **有用性正控通过。** P01 保留三句，P03/P04 保留有依据的多事实，P05 保留限定后的事实，P07 保留背景；可采用受控重建而不强求保留模型措辞。若只能拒绝所有结果，不验收。
3. **难负控不能伪绿。** 至少核查循环错引、改写绕过、否定、时点、主体翻转、多事实部分支持。算法若只是覆盖集合/相似度/短串匹配，即使原两例绿了仍不足通过。
4. **摘要传播关闭。** 每条进入摘要的事实来自被认可的分项/安全来源；长度截断、三引用上限和去重均不能留下文本而移除支持。空结果不能触发 `items[0]` 等异常。
5. **范围与语义状态分离。** draft coverage 是供给和引用范围；item support 是该条语义来源关系。全 claim ID 引齐不等于全内容得到正确复述；发生重建/删项/截断应可复核，不能通过重新定义标签掩盖缺口。
6. **真实链路与保存后重读。** 至少以正常三句和长句走一次分析 API 到持久化，再重读/刷新，核对正文、引用 excerpt、范围信息与后台结果一致。实际工作台应仍能呈现有内容的简报与来源；修补范围不要求重做整个 UI。
7. **来源构建的局部回归。** 如果改动了共享 draft claim / SourceSpan 构建，核对其余使用者没有因 ID、偏移、token 上限、版本绑定改变而错误；不扩大成无关全项目改造。
8. **证据身份保留。** 历史 V1/V2/V3 请求、首答、失败和评审不回写。旧冻结 runner 的源 hash 校验失败不应通过改旧常量绕过；产品修补后使用新的 run 身份/冻结清单。离线复放证明产品守卫修复，真实新答另行计分，不能把产品重写写成模型首答正确。

## 不在本轮作出的承诺

本轮不要求证明任意小说文本的通用蕴含关系，也不把规则验证包装成完整语义理解。目标是关闭已有可复现的自身引用缺口，增加具有反例区分能力的局部防护，并保留正常简报的实际用途。更广泛的模型能力、V8 检索门槛、Agent 和真实作者研究保持原边界。
