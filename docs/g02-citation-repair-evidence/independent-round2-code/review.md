## 首轮容量问题：关闭

原强反例仍是 12 条不同、有效、自身引用正确的模型 items：一条四来源灯色、八条不同 Memory、最后三条正常草稿事实。第一轮结果只保留 c1、丢掉 c2/c3。

本轮结果：

```json
{
  "draft_facts_preserved": {"c1": true, "c2": true, "c3": true},
  "output_item_count": 12,
  "draft_coverage": {"status": "covered", "uncovered_source_ids": []},
  "citation_transform": {
    "version": "source-rendered-v2",
    "fallback_draft_claim_ids": [],
    "duplicate_omitted_item_count": 0,
    "overflow_omitted_item_count": 3
  }
}
```

`engine.py:519–542` 现在先为选中草稿来源保留位置，再填背景项。原模型已经提供的三个草稿分项都被保留，不再靠仅第一条 fallback。容量仍有界，三个可选背景展开项被省略且数量明确披露；这与主控要求保留正常草稿事实、允许有限背景缩减一致。

独立补充正控：

- 模型三次重复只给 c1，最终去掉两张重复卡，并补 c2、c3；`duplicate_omitted_item_count=2`，`fallback_draft_claim_ids=[c2,c3]`，三条不同事实全部保留。
- 三个短事实共同引用三条 claim 时保持一张完整卡，三个事实均在、coverage covered；不会因为依次给 claim 预留而复制同一张卡。
- 普通三句、循环错引的改写、坐标能力与知识未知的多来源分项、可容纳的长句尾部继续通过。

这些正控避免把“优先级字段存在”或“最后有 12 条”误当成有用性通过。检查的是实际文本、引用和事实保留。

## 引语修复：限定通过，并验证真实构造分支可达

仅直接调用 splitter 不足以证明产品使用它。因此本轮抽取并执行 `v2_database.py` 中真实的 `draft_parts` 分支及其 claim 构建循环，用独立字符串核对文本、偏移、截断范围，再送到实际 validator 检查所有完整引语是否保留。

以下五组均通过切分预期、源字符偏移和最终分项保留三项检查：

1. 两个人连续发言，中文弯引号内有句号；每条 claim 保留说话者和闭引号。
2. 弯双引号内嵌弯单引号，内层含感叹号；完整外层发言不被内层标点拆开。
3. `「」` 中嵌 `『』`，内层含句号；闭合与外层叙述完整。
4. 句号在闭引号之外的发言。
5. 同一完整发言中含两个句子，然后是独立的旁白句。

每组同时给出错误/不完整模型措辞，最终仍能保留实际选中完整引语和后续草稿事实。另核对只有 context_brief 使用新切分与 540 字额度，`story_qa` 相同长材料仍保留原 240 字限制，未无意扩散修改。

否定、时点、明确谎言及反转关系的首轮正负控制也继续通过：最终展示来源原文，不把模型措辞升为已验证叙述者事实。

## 保留限制，未作为本轮新增阻断

**Author Context 双正文字段。** 首轮 11 项复放是 10 项通过、1 项条件性观察仍失败：手工向 validator 同时传非空 summary 和 goal 时，renderer 会拼接二者，但 `_clean_source` 只显示首个正文域。当前实际 DB mapper 的该类 goal 等并行域为空。本轮补测与当前 mapper 相同的 summary + 空 goal 输入，正文、自身 excerpt 和 related_plan 层级均正确。未证明旧双正文反例从当前正常业务路径可达，所以不将其升级为本轮业务失败；将来扩展输入形状时必须统一渲染和引用投影。

**splitter 的语言/句法边界。** 新 splitter 明确只处理四组弯引号和中文角引号。独立观察确认：ASCII 双引号仍会被内部句号拆开；引语后的说话者“‘……。’温岚低声回答”会分成两条；作为更长句子成分的问句引语也可能在闭引号处提前分段。原文字符仍在后续 selected claims 中，但不能声称已实现通用多语言发言者绑定或所有小说引语完整性。见 `boundary-results.json.recorded_splitter_limits`。本轮目标中出现的前置说话者与正常中文完整/嵌套引语已验证，不要求本次扩展成通用句法分析器。
