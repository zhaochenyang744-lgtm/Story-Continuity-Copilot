# V11 类别判定修复（预算中性版）：冻结计划

日期：2026-09-28。缺陷定位、新对照集设计和评分方式与 [V10 计划](../model-compare-v10-independent-acceptance/PLAN.md) 相同，本文件只记录差异。

## 为什么撤回 v19

V10 运行中，后端全量测试显示 v19 类别规则（2,035 字符，比 v17 的 1,107 字符长 928）使 continuity prompt 每次多占约 232 个预算单位，接近上限的长篇请求越过 6,000 输入预算：新增 5 项 `input_budget_exceeded` 失败，这些测试中没有发出 Provider 调用。这是会上线的产品回退，因此 v19 不可发布。V10 在 18/108 个条件案例、20 次 POST 后由主控停止，部分结果保留但不评分、不比较，见 `evaluation/model_compare_v10/runs/model-compare-v10-20260928-01/ABORTED.md`。

## 产品修改（prompt v20）

`continuity-review-v20-decisive-fact-category`：保留 v19 的全部判定原则（按决定性事实分类；有行为记录而无执行者/原因即为 relationship；带时间锚点的固有属性仍是 attribute；只下定义的规则是前提，仅在规则单独构成反驳时用 world_rule），压缩为 1,105 字符，不超过 v17 原规则。空请求 prompt 预算与 HEAD 类别规则相同（增量 0）。受影响的后端测试模块与 HEAD 逐项对比，失败集合相同，无新增失败。离线测试新增长度上限断言，防止再次超出。

## 评测设计

与 V10 相同：34 个已见 V7 输入＋20 个 category-controls-v1 新对照（v19 调用前已冻结，未修改），Flash high 与 Pro high 各跑 1 次，108 个条件案例，432 次 POST 上限、1,500,000 已知 token 停止阈值。V10 已发出的 20 次调用中包含部分对照案例的 v19 回答；它们未被查看或评分，但严格地说这些对照已被同一实施者的早期版本接触过，记录在此。

## 不在本轮范围

独立标注的未见集、重复运行稳定性、原预算端到端、检索/数据库/API 链路、上线。
