# v1.3.0 Story Memory fact lifecycle

Technical appendix to the canonical [v1.3.0 product contract](v1.3.0-product.md).

v1.3.0 extends the existing Story Memory review with three explicit fact changes:

- `new_fact` proposes a fact that does not collide with active confirmed memory.
- `changed_fact` binds one exact active Memory record and shows the confirmed fact before the proposed replacement.
- `invalidated_fact` binds one exact active Memory record and records why it should stop applying. It retires that fact with `valid_to`; it does not delete history or invent an opposite fact.

The AI request contains only bounded SourceSpans from the new source revision, active confirmed Story Memory, controlled predicates, and the exact output schema. Author Context, future plans, and writing-alignment analysis are excluded. Unknown fields, invalid references, duplicate targets, unsupported predicates, unresolved Evidence, and stale source or Memory bindings fail closed before candidates are persisted.

Authors decide every core change before submission. New and changed facts may be accepted, edited with the same current-revision Evidence, or rejected. Invalidated facts may only be accepted or rejected. Supporting suggestions remain outside confirmed Memory unless the author explicitly decides them.

One successful submission creates an immutable Memory version and an auditable ChangeSet in the same SQLite transaction. The ChangeSet records the base and target versions, author, paired analysis Run, before and after values, Evidence, decisions, and add/replace/retire operations. A fully rejected review or a review with no candidates creates coverage and decision audit records without increasing the Memory version. Any failure rolls back the complete submission.

Desktop review stays on the existing Story Memory page. Narrow screens remain browse-only: facts, before/after comparisons, Evidence, source drawers, coverage, and ChangeSet details are readable while all mutation controls are disabled.
