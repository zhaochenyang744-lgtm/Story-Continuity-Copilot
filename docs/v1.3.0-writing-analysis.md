# v1.3.0 writing analysis

Technical appendix to the canonical [v1.3.0 product contract](v1.3.0-product.md).

v1.3.0 adds two secondary actions to the existing Writing page and one to the character archive:

- **生成章节简报** prepares a bounded pre-writing brief covering relevant plans, confirmed facts, character state, world rules, unresolved items, and recent written sources when available.
- **检查计划偏离** compares the current saved draft with each retrieved story plan and returns only `planned_covered`, `planned_missing`, `planned_early`, `planned_changed`, or `insufficient_evidence`.
- **分析影响** evaluates an explicit author proposal against bound project evidence and lists only affected supplied records with resolvable citations. Its detailed contract is in [character aliases and change impact](v1.3.0-character-alias-impact.md).

The data layers remain explicit throughout request, storage, and presentation:

| Layer | Source | Meaning |
| --- | --- | --- |
| planned | Author Context snapshot | Author intention, not canon and not written evidence |
| confirmed | Story Memory version | Author-confirmed facts |
| written | Saved draft claims and SourceSpans | Text already written |
| analysis | Immutable analysis result | Provider conclusion, never an automatic edit |

Each analysis Run binds the project, draft ID and revision, source revision, Story Memory version, Author Context version, snapshot digest, Provider/model labels, prompt and schema versions, and deterministic retrieval method. Change impact additionally binds the project alias version and snapshot digest. The change-impact surface exposes the human-readable binding versions and retrieval method beside the proposal, including while queued and after staleness; snapshot digests remain audit data rather than routine interface copy. A result becomes stale when any bound state changes. Retry creates a new Run over the same immutable input and is rejected when the lineage is stale.

Retrieval is deterministic and bounded. The stored input records selected IDs, available and selected counts, truncation flags, a retrieval version, and an input digest. The Provider receives no entire novel, tools, vector database, or external-search access. DeepSeek requests keep thinking disabled, temperature 0, JSON-object mode, and hard input/output limits.

Invalid JSON, schema violations, unresolved evidence, timeout, cancellation, and budget stops are terminal fail-closed outcomes. They write no partial analysis result. Change-impact output with zero items is not allowed to preserve an unsupported Provider conclusion: it becomes a deterministic evidence-insufficient result. Completed context items resolve only to `author_context`, `memory_record`, or `source_span`; plan-alignment evidence resolves to current-draft claims or SourceSpans. All resolved sources use existing product routes and stable record anchors. Planned material is displayed as a plan source and never as proof that text was written.

Desktop users can generate, cancel, and retry. Narrow screens are browse-only: existing conclusions and sources remain readable, while trigger, cancel, retry, and author-decision controls are absent. Editing remains available independently of analysis failure or staleness on supported desktop widths.
