# V6 语义验收标准 v1

2026-09-27；设计基线 `7d811cc9a3fb76f3cfbe60492399d6c0fc9e07b2`。本标准先于V6实现/真实输出锁定，是开发控制，不是盲测。主控已确认本轮采用**故事事实主命题**，不新增独立source_attribution issue或大幅扩展schema。控制与输入hash见 `control-matrix.json`；未执行任何控制、Provider或数据库操作。

## 1. 联合证据的方向与充分性

`relation`始终相对正在审阅的草稿主命题P，不相对“模型这次推理是正确的”。`supports`表示支持P，`contradicts`表示在已明确绑定的实体/时间/规则范围内反驳P，`context`可以承担身份连接、规则前提或相关背景。身份/规则是**证明角色**，不是自动反驳P；用现有chain和简短reasoning表达即可，不要求本轮新增大schema。

确认冲突必须有完整的联合证明：必要身份/规则前提和真正不相容的事实都在该issue自身引用中；后者至少一条。身份链接可以使“西镜片透明”反驳“Q8琥珀”，但只剩西镜片描述时不能假定它就是Q8。抽象就绪规则也不能代替当前阀帽状态。允许选中、相关且明确标作可选的context；它既不能承担缺失的必要前提，也不能把不完整证明补成充分。真正支持P的证据不得被重标contradicts来通过。

充分性在**整组来源对完整主命题**层面判断。若沿用单条`sufficiency`字段，必须在V6合同说明其角色含义；不得由每条标sufficient或“至少一条contradicts”推定整组已充分。禁止context/supports批量翻成contradicts，禁止检验时仅删掉造成失败的引用而隐去被删除的首答。每层均保留原始关系和产品处理差异。

机器可验证ID、章节、selected范围、Memory反向绑定和合同结构；自然语言身份/因果/规则的完整覆盖仍需独立语义检查。**结构pass不等于联合证明正确**，不能用词面相似度或“任意出现rule”充当证明。无需按case_id、expected_class、具体名字或控制答案在产品里特判。

## 2. 不足与合法空结果

有来源担保/推断依赖的P缺失关键身份、授权、责任、先后或信息转移：返回insufficient，指出具体缺口；不把空白记载当P为假，也不返回空issues掩盖未完成判断。保持context/insufficient、missing_link、无编辑/建议/Memory变更。

普通相容的新情节不因旧材料没提到就成为不足；草稿明确写出的后来行动本身可构成转变。当前八个无冲突案例必须全部保留，包括谎话框架、昨日主观回忆、合法学习和位置变化。允许的state_change非空对象不计冲突；若发出仍须足够的前后依据，无需强制每例都发变化项。

## 3. “记录确证P”的两个命题

区分故事事实P与归属命题“记录确证P”。记录明说顺序未记/同伴未命名时，归属担保不成立，但P仍未知。本轮主结果固定为**insufficient**，解释必须同时讲清“记录不支持此归属”和“尚不能断言P或非P”。不能返回confirmed故事冲突、无issue、编造相反事实，或用无日期=timeless_rule绕过时间校验。

V5的15/24文献归属解释有可辩护之处，这个历史限制继续保留；V6选择的是预先声明的产品目标，不是发现新逻辑定理。出生先后用timeline；具名责任/递送/授权用relationship；同伴location_action/relationship仍逐答人工裁定，character_knowledge不能仅凭“记录告诉了什么”自动成立。

## 4. 验收与版本

先过12个新控制和八个既有无冲突保底案例，分开记录结构与语义；控制payload不算模型样本。C02缺联合前提的完整性是语义否决项，C05未选SourceSpan是确定的绑定拒绝项，不夸称同一结构校验能够证明任意自然语言。

V6须显式标识合同、提示词、评分器和输入版本；逐项列出混合关系、可选context、集合充分性及归属目标的变化。旧24输入可以新版本引用，旧gold/冻结/V5首答和成绩不动。V5原答按V6离线重评分只说明合同适配；不能冒充新调用、能力提升或修复后的首答成绩。真实首答、修复和最终产品分别验收，失败/超时不计无冲突。
