## Reproduction and intended behavior

The saved V2 G02 long-sentence request contains a 299-character draft excerpt but a 240-character draft claim. Model item 1 and final summary mention the tail, while that item's only citation ends at character 240. Item 2 combines a correct tide-coordinate observation and a correct unknown-code observation, but cites only a Memory that supports the latter; the actual chapter SourceSpan supports both. All four first-model summaries mention facts beyond their own one to three `summary_sources`. The final product already rebuilds summaries from items, yet the long-sentence item carries its unsupported tail forward. Original model JSON and final outputs are retained as the first-failure chain.

For context briefs, supply up to 540 characters of each selected draft claim, within the existing eight-claim selection, and keep truncation metadata truthful. This leaves room to display the full claim with its attribution inside the existing 600-character item limit. The 299-character sentence then has a single complete direct claim citation. A longer claim can still be partial; no coverage label substitutes for item support.

After source-ID resolution, use phrase overlap **only to locate candidate sources**, never to certify that freeform model wording follows from a source. The final item is reconstructed as an attributed quotation of each selected draft claim or SourceSpan, or as an explicit structured Memory/plan record. A direct quote preserves dialogue, negation, time and attribution instead of converting a substring into an asserted story fact. A citation is added only when the corresponding bound source is rendered in that same item. Unmatched model clauses are omitted from final text; if no relevant supplied source can be located, discard that item and keep the existing deterministic cited-draft fallback where applicable. Keep transformation and omission counts in product metadata and the untouched first-model JSON in run evidence. Rebuild the final summary only from reconstructed source-backed items and their own sources, respecting the three-source and 400-character limits; when a combined item needs more than three sources, use a nonfactual summary fallback.

Candidate search will distinguish close negative/time alternatives such as 已交/未交 or 今日/昨日 even when most words overlap, but selection itself is not a semantic verdict. Legitimate wording variation can still lead to the same correct evidence being chosen and then rendered with its own attributable wording. A model's first summary is not silently declared correct because the final summary is repaired. The deterministic path proves only that displayed quotations/record fields come from the cited bound inputs; it cannot prove the model's freeform paraphrase or that cited story dialogue is true in-world. The UI and handoff must maintain this distinction.

## Verification matrix and risk

- Offline pre/post replay of the two V2 long-sentence bad items and first/final summary, plus existing three-sentence, identical-text and body-limit positive controls. Include a multi-fact sentence; cyclic cross-item citation mismatches; facts correct somewhere in input but cited to the wrong own source; sufficient paraphrase with full own support; unrelated near text and negation/time near misses; >600-character truncation and source-count limits. Assert no item remains with an uncovered known clause and summaries inherit only accepted cited facts. Test product API on isolated synthetic SQLite projects and preserve failures.
- Run affected backend writing-analysis, Provider contract and relevant UI tests. Browser verification uses an isolated local synthetic app: create/save a draft, run brief, expand cited source, refresh and confirm persisted result and citation navigation. Record render/interaction evidence. Do not touch the live business DB.
- New real G02 run after offline checks: exactly four prior bodies plus at most two new synthetic bodies, one logical run each. Product bounded repair/transport retry may increase actual POST count and will be counted. One `/models` preflight is separate. `deepseek-flash`, `https://api.deepseek.com`, existing JSON mode/temperature/timeout/limit. Freeze new cases, scorer, runner, prompt/engine/DB/seed dependencies, relevant tests and parameters **before** real dispatch. Save full credential-free business requests, first and every repair answer, terminal product result, citations, actual dispatch/usage and unknown usage; cost is unavailable unless returned. No key, HTTP header, raw body or hidden reasoning is saved. Use a new result identity and isolated DBs. Quality failure is retained rather than rerun repeatedly.
- Risks: longer claims increase prompt size; bounded citation repair may remove useful paraphrases or still miss unsupported semantic claims. Report both. Prompt/model alias can drift; report returned model/fingerprint. G02 totals are incremental to the already accepted 57 POST / two preflight accounting, never merged into a same-input accuracy rate.

## Current-contract comparison set, not an execution authorization

Create a separate versioned, **seen development/comparison** asset with recoverable original synthetic corpus, case IDs, labels, required source IDs and source text, allowed alternatives, nearby positive controls and scoring rules. Map old V8 cases to retained, adapted or excluded entries with reasons. Include `confirmed_conflict`, `no_conflict`, `insufficient_evidence`; full versus insufficient direct evidence; `rule`/`timeless_rule` versus dynamic state with explicit time windows and legal future change. Do not relabel `static_canon/fixture_anchor` as `rule` merely to force a desired answer. Add an offline fixture/input/label preflight and a new hash manifest. Do **not** run the whole comparison set against the real model in this phase; independent review decides later.
