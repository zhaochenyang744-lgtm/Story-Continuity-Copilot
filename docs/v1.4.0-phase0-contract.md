# v1.4.0 阶段 0：可信审阅与草稿恢复契约

日期：2026-09-05  
状态：前端实施基准；后端与真实模型效果尚未实施  
基线：`ce5b717034e7e83c498622356e7250dde53054da`

## 1. 范围与不可越过边界

本文件冻结 v1.4.0 阶段 1 前端所依赖的产品语义、兼容方式和验收样例。产品仍是个人 AI 创作工具。本阶段不修改业务后端、正式教学 seed、既有冻结评测材料或 `.env`，不调用真实 Provider，不把前端桩数据描述为后端已支持。

前端必须对旧接口 fail legibly：缺少新字段时显示“性质待确认”或“当前接口未提供”，不能依据风险等级、问题文案关键词或 Memory 版本号推造业务语义。

## 2. 判断、证据与作者决定行为矩阵

### 2.1 字段职责

| 维度 | 允许值 | 作者视图 | 禁止行为 |
|---|---|---|---|
| `nature` 问题性质 | `confirmed_conflict`、`possible_conflict`、`state_change`、`insufficient_evidence`、未知 | 明确矛盾、可能矛盾、状态变化、证据不足、性质待确认 | 不得由 `severity`、`category` 或说明关键词推断 |
| `severity` 影响程度 | `high`、`medium`、`low` | 高影响、中等影响、低影响 | 不得显示成问题性质 |
| `category` 涉及资料 | 现有属性、位置、时间、知识、物件、关系、世界规则、事件进展等 | “涉及：角色所知”等辅助标签 | 不得把“位置变化”直接解释为矛盾 |
| `evidence_status` 证据状态 | `sufficient`、`insufficient`、`unavailable` | 证据充分、证据不足、证据不可用 | 证据不足时不得开放会记录作者决定的动作 |
| `valid_from/valid_to` | Memory 版本号或空 | 技术详情中的“事实库版本 Vx—Vy/当前” | 不得显示为故事章节或推断故事时间 |
| 来源章节 | `source.chapter_number/title` | 主视图可定位的章节来源 | 不得与事实版本合并成“第 x 章开始持有” |

### 2.2 问题性质

| 性质 | 成立条件 | 主视图语言 | 默认后续动作 |
|---|---|---|---|
| 明确矛盾 | 同一适用时点/范围内存在不能同时为真的事实，且证据链充分 | “明确矛盾” | 查看证据；前往修改；保留原意；标记误报 |
| 可能矛盾 | 有冲突迹象，但时间、视角或适用范围仍需作者确认 | “可能矛盾” | 查看证据；保留原意；标记误报；有具体修订才可采用建议 |
| 状态变化 | 新文本描述从旧状态向新状态的演变，未证明同一时点冲突 | “状态变化” | 解释变化；可进入事实候选审阅；不得仅凭变化升级成高风险矛盾 |
| 证据不足 | 关键交接、得知信息、时间先后或来源缺失 | “证据不足” | 查看已检查范围；停止判断；不记录确定性作者决定 |
| 性质待确认 | 旧接口没有 `nature` 或值未知 | “性质待确认” | 仍可读已有证据；不由前端补判 |

伏笔、人物说谎与作者刻意安排不是独立“错误类型”。它们作为证据解释或作者决定记录，直到后端提供明确、可审计的产品契约。

### 2.3 按钮与后果

| 动作 | 显示条件 | 点击后的直接结果 | 不会发生 |
|---|---|---|---|
| 前往修改 | 可编辑且证据可用 | 关闭问题抽屉，聚焦正文，建立受控编辑上下文 | 不自动改正文、不保存、不写 Story Memory |
| 采用建议 | 后端提供可定位的具体修改前后文本 | 先展示 `before/after` 差异；作者明确应用时再次校验正文与唯一定位，成功后才写入未保存草稿 | 取消不改正文；不自动保存、不自动提交事实 |
| 保留原意 | 可编辑、证据可用且未处理 | 只记录本条提示的 `keep_intentional` 决定 | 不改正文、不提交事实 |
| 标记误报 | 可编辑、证据可用且未处理 | 只记录本条提示的 `false_positive` 决定 | 不改正文、不提交事实 |
| 加入事实候选 | 后端明确返回支持此动作且存在事实候选 | 进入候选审阅 | 不直接写入 Story Memory |
| 提交事实审核 | 所有候选有作者决定且版本仍匹配 | 原子创建新的 Memory 版本 | 不与问题决定隐式合并 |

所有决定动作前必须展示一句可读后果。证据不足、来源不可用、旧检查过期或版本不匹配时，确定性决定按钮禁用，并说明原因。

## 3. 前后端接口差异与兼容方式

### 3.1 当前接口事实

- `Issue` 目前有 `category`、`severity`、`evidence_status`、`explanation`、`claim_text`、`evidence` 和既有 `decision`，没有独立 `nature`、判断理由结构、具体修订差异或动作能力。
- `Memory.valid_from/valid_to` 是事实库版本字段；来源章节在 `Memory.source.chapter_number/title`。
- `PATCH /projects/{project_id}/drafts/{draft_id}` 使用 `base_revision` 做版本校验；当前设备恢复不需要新增写接口，恢复副本只有再次显式保存才写服务器。
- `POST /api/onboarding/progress` 的正式契约仍为教学 `1.2.0` 四个事件。本阶段不修改该接口或正式 seed。
- `POST /imports/preview` 接收浏览器发送的 `FormData` 文件；确认导入前不会创建作品，但“原始文件不会上传”不符合现状。

### 3.2 后续阶段建议的可选增量

保持旧字段兼容，建议在 `Issue` 增加：

```json
{
  "nature": "confirmed_conflict",
  "reasoning": "为什么这些证据支持此判断",
  "evidence_chain": [{ "evidence_id": "...", "role": "prior_state" }],
  "suggested_revision": {
    "before": "正文中可唯一定位的原文",
    "after": "具体候选文本"
  },
  "available_actions": ["edit", "keep_intentional", "false_positive"]
}
```

兼容规则：字段缺失时前端显示未知，不回填推断；未知枚举保持可见；只有 `suggested_revision.before/after` 完整且能唯一定位时显示“采用建议”。`available_actions` 未提供时沿用现有安全动作集合，不显示“加入事实候选”。

建议将判断理由与证据链做结构化增量，但阶段 1 可先用现有 `explanation` 与逐条 Evidence 呈现。后续后端需保证每个引用在语义上支持对应结论，不能只保证 ID 存在。

## 4. 教学剧本与进度规则

教学仍使用同一隔离作品，并围绕“看懂—查证—决定—回写作”展开：

| 步骤 | 目标 | 对应可操作位置 | 唯一推进事件 |
|---|---|---|---|
| 1 | 理解 Story Memory 是作者确认的事实快照 | Story Memory 事实行 | `memory_source_opened` |
| 2 | 从来源返回并进入当前草稿 | 来源抽屉关闭、写作与检查入口 | 不提前写事件；导航本身不推进 |
| 3 | 识别真正矛盾，同时看见状态变化与证据不足不是同一性质 | 问题列表 | `continuity_issue_located`，只在真实打开问题时写入 |
| 4 | 对照当前原文、历史依据、判断理由并决定 | Evidence 抽屉 | `evidence_opened` 后保持在本步，直到真实决定 |
| 5 | 确认决定后果，查看事实候选入口并返回写作 | 决定反馈与完成按钮 | `author_decision_recorded` |

首次进入显示目标；恢复历史进度时明确“已恢复到第 n 步”。当前 `POST /onboarding/reopen` 会通过 `reset(..., reason="demo_recovery")` 重置教学作品，不能接成“仅重置进度”。阶段 1 只展示“安全重新开始尚待接通”，并在隔离测试 fixture 演示目标交互；阶段 2 必须提供 progress-only 接口，回到第 1 步且不改变教学作品内容，才能开放生产按钮。教学条可最小化并在原位置重新展开。阅读来源只能要求“返回问题”，不能要求在只读来源页作决定。

正式 seed 的故事内容与后端进度语义属于阶段 2；阶段 1 只可在隔离的前端测试 fixture 中展示“明确矛盾、正常状态变化、刻意保留伏笔、证据不足”四种状态，并标注为测试数据。

## 5. 当前设备草稿恢复与冲突规则

本地键按 `schema_version + user_id + project_id + draft_id` 隔离，记录 `base_revision`、标题、正文、更新时间，不包含 Story Memory 或检查结果。

| 场景 | 行为 |
|---|---|
| 输入后未保存 | 立即写入当前浏览器本地恢复副本；状态为“未保存 · 已留在当前设备” |
| 刷新/重新进入，服务器 revision 未变 | 提供“恢复副本”与“使用已保存版本”，不自动覆盖 |
| 服务器 revision 已变化 | 显示版本冲突并始终保留两份完整可选择文本；作者先选“以服务器新版为基线继续编辑”或“保留恢复副本另行处理”。仅选择恢复副本不授权用服务器新 revision 覆盖；在没有后端合并/冲突确认契约前，禁用直接覆盖式保存 |
| 保存成功 | 只提交请求开始时的精确快照。响应返回时若作者又输入了 B，只更新服务器基线为已保存的 A，保留 B 为未保存内容及本地副本；不得用 A 覆盖 B，也不得删除 B 的恢复键。旧检查标记为针对先前正文 |
| 保存失败 | 保留本地副本，显示失败原因与重试按钮，不得显示“已保存” |
| 受控修订部分成功 | 若正文保存成功、随后决定接口失败，分别显示“正文已保存；决定未记录”，保留可重试的决定上下文；不得笼统显示正文保存失败 |
| 切换账号/作品 | 只读取新身份和新作品对应键，不展示其他键内容 |
| 退出登录 | 本地副本保留在当前浏览器，但由用户键隔离；下次同账号进入才提示 |
| 归档/删除作品 | 不自动把副本写入其他作品；后端真正删除能力落地时需同时清除精确键 |
| 存储不可用 | 明示“当前设备恢复不可用”；仍允许显式服务器保存，不声称有本地保护 |

保存请求绑定发起时的 `user_id/project_id/draft_id/base_revision` 和内容快照。迟到响应若已不属于当前身份、作品或草稿，只能丢弃当前界面写入，不能清除新上下文的本地键。保存进行中可选择锁定编辑；若允许继续输入，则必须遵守 A/B 快照规则。页面离开与关闭沿用未保存提醒；`Ctrl/Cmd+S` 触发现有显式保存。恢复副本不进入 Story Memory，也不会使旧检查重新有效。

## 6. 新开发样例与基线设计（不改冻结评测）

新样例使用自创的“雾港档案”小型故事，置于 v1.4.0 新目录，不修改 `evaluation/case_sets`、`evaluation/fixtures` 或历史结果。样本在进入检索优化前分为“开发样例”和“独立保留验证样例”：开发样例可用于诊断与调整，保留集在冻结后不得用于反复调参、提示改写或选择实现。

| 样例 | 目标 |
|---|---|
| 跨章交接 | 第 2 章甲持有钥匙，第 9 章明确交给乙；检索需包含交接链，不能把 Memory V2 当第 2 章 |
| 同时持有人冲突 | 同一时点甲、乙都被写成唯一持有人；应为明确矛盾 |
| 正常位置变化 | 随身保管后主动放到桌上；应为状态变化，不仅凭变化判高风险 |
| 别名 | “温岚/阿岚”指向同一人物；远章证据不能因名字变化遗漏 |
| 倒叙 | 叙述顺序与故事时间不同；证据不足时停止，不按章节号强排故事时间 |
| 人物说谎 | 角色台词与事实不一致但叙事明确其在说谎；作为作者解释，不直接判事实错误 |
| 伏笔保留 | 作者明确保留表面矛盾；决定只处理提示，不自动写事实 |
| 缺证据 | 关键得知过程缺失；输出“证据不足”，不输出确定性矛盾 |
| 远处规划 | 问题目标与较远规划相关；问答检索不能只取前几条规划 |

开发集和保留集分别保存清单、内容哈希、版本与用途；保留集只在候选冻结后执行，并保留原始失败。离线基线按“关键证据召回、结论正确性、引用支持性、状态变化误报、正确停止判断、作者有用性”分项记录。数值门槛必须在记录现状基线后、开始优化前确定并冻结；真实调用授权只授权约定模型、文本范围和预算内的执行，不授权使用保留集调参。本阶段不运行 Provider，也不宣布 AI 效果提升。

## 8. 当前未决项与阶段 2 依赖

1. 后端需确认 `nature` 枚举、判断理由、证据链、具体修订和动作能力的最终字段名与兼容版本。
2. 正式教学 seed 需重写成一条故事并做语义引用审查；阶段 1 fixture 不能替代它。另需新增只重置教学进度、不调用作品 reset 的 progress-only 重新开始接口。
3. “加入事实候选”的后端入口、候选内容与事务边界尚未提供，因此生产前端不显示伪入口。
4. 草稿恢复目前是当前设备能力；删除作品后清理精确键需要后端删除生命周期信号。
5. 检索、别名、远规划、真实模型效果和作者任务观察仍属于阶段 2/3；不得由本阶段视觉结果推断已提升。
