## 三类案例分开管理

| 分类 | 目的 | 维护要求 |
|---|---|---|
| 开发回归集 | 检查已知问题是否重现，允许用于调试 | 新缺陷归入此类；反例尽量配相近正控制，防止通过“一律拒绝”获得表面正确 |
| 固定比较集 | 比较模型、提示词、检索和产品版本 | 冻结输入、标签、评分规则和阈值；同条件比较。已看过的案例不再宣称“未见” |
| 独立未见集 | 检查对新材料的泛化 | 与开发材料按作品／语料家族隔离，改名或近似改写不能算独立；记录接触与调试历史。案例一旦用于修复，后续归入已见回归，并补充新的未见材料 |

上述为目标分类，不能据此宣称新的未见集已经建立。三类分别报告样本数、来源、指标和限制，不能混成一个准确率。

## 何时维护与执行

- **每次确认缺陷**：提炼可复现的最小案例，记录首次失败及相关需求；修复后保留失败证据与通过证据，补相近正控制，并检查同类边界。
- **每次修改模型、提示词、检索、工具、输出校验或编辑交互**：在交付说明中列出受影响能力与案例，执行有必要的离线回归；真实模型变更效果须由明确授权的实测支持。
- **每个里程碑验收前**：盘点覆盖缺口、失效案例、重复案例、未见集接触情况和材料可恢复性；核对适用的回归及比较结果，未执行项明确标记。真实评测的调用额度、重试、费用上限或费用不可得时的请求硬上限，应在运行前确定。
- **项目持续迭代期间每月一次人工盘点**：更新资产状态及待办，检查来源与证据能否恢复；不要求无变化时重复运行昂贵评测。本条是维护节奏，不创建定时任务或自动付费调用。
- **新增能力时**：需求和评测设计一起交付。未来 Agent 的工具选择、参数正确性、多步完成、失败恢复和确认边界须另补专项案例；仅在 Agent 开发明确启动后纳入实施。

实施者负责提供案例、变更理由和自测证据；独立验收者复核预期标签、关键反例、正控制和结论范围；用户接受结果与版本发布继续作为独立步骤。

## 案例记录的最低要求

新增或修订案例至少记录以下内容；可通过侧边清单引用现有格式，不要求改写旧冻结文件。

- 稳定的 `case_id`、案例修订号、能力标签、风险级别、关联问题及首次发现日期。
- 来源与使用许可／授权、语料家族、合成或真实来源标记、所属分组，以及是否曾被用于调试。
- 输入材料的可恢复位置与哈希、必需上下文和执行前提；使用独立合成材料优先，敏感用户文本须经授权和脱敏。
- 预期结论、直接支持证据、允许的等价输出、禁止行为和评分规则；开放性任务明确人工判断边界。
- 标注者、独立复核者、复核日期及争议说明；未解决标签争议时不得把结果计入正式质量通过率。
- 首次失败、新的通过记录及其 `run_id`；废弃／替换原因和替代案例 ID。

发现旧标签错误时追加勘误记录，发布新的案例修订或集合版本；保留原标签、原评分和失败链。不因模型答错而直接改成匹配模型答案。

## 版本、运行与结果保存

1. **集合与代码独立标识**：案例、语料、标准答案、评分或阈值的变化形成新的版本／修订及哈希清单；记录增删改内容、原因和复核状态。
2. **每次运行有唯一身份**：记录 `run_id`、集合与语料哈希、代码 commit、必要的未提交差异标识、模型标识／可得版本、提示词版本、参数、检索配置、评分器版本和开始／结束时间。模型别名可能漂移；只记录服务实际提供的信息，不虚构固定版本。
3. **先定规则再看结果**：运行前锁定评分规则、阈值、样本、调用与重试额度。更改后另开运行记录，不能追改原结果。
4. **失败也是结果**：保留首次失败、超时、额度拒绝、中断和修复历史。区分配置事故、执行失败和质量不达标；写清所有尝试及计入指标的分母，不能只报告成功重试。
5. **分别衡量模型与产品**：模型首次输出、重试后输出、产品校验／降级后的输出分开统计。检索、引用、覆盖、格式和端到端行为分别给出证据，不用守卫通过率代替模型准确率。
6. **用量如实记录**：实际 HTTP 派发与逻辑请求分开计数。超时造成用量未知时不得当作零；已知部分单独保留，不能当成完整总量。费用不可得时标记不可得。
7. **版本比较有边界**：先用共同案例与相同评分器逐例比较，再单列新增案例；集合变化时不能只用整体分数变化推断质量提升。稳定性追加调用不能计为新增独立案例。
8. **保存可复核材料**：Git 保留许可允许的案例／脱敏材料、标签、清单、评分器、复现脚本、逐例脱敏结果和报告；不得仅有哈希而无可恢复材料。数据库、会话、凭据及原始浏览器 trace 不直接入库；需要保留的运行证据使用受控位置与保存清单。缺失资料明确标为不可完整复现。

**现有 V8 入口不能直接用于新一轮评测。** `evaluation/execute_v8_first_formal.py` 固定案例、模型／提示词、结果路径和 24+6 协议，并拒绝既有输出；历史校验器也绑定冻结哈希与结果。新一轮先实现并审核独立的新版本／新运行入口及验证规则，确保不同输出位置与身份。保留旧入口和校验器作历史审计，不解除防覆盖保护，也不将旧冻结 manifest 中的执行前快照字段改写为新运行状态。
