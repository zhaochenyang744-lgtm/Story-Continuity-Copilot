# Character aliases and change-impact analysis

Character aliases are an independent, author-confirmed identity layer attached to written character records. They are not Author Context, Story Memory, source prose, or archive-derived guesses. Adding, editing, or archiving an alias changes only the alias tables and their project and character version counters.

Each character alias set uses a zero-based optimistic version. Writes require `Idempotency-Key` and the current `base_version`. Normalization uses Unicode NFKC, collapsed whitespace, and case folding. An active alias cannot duplicate the primary name or another active alias for the same character, and one character may have at most 20 active aliases. Archived rows remain available for audit. Project and account ownership is checked before character or alias lookup, so out-of-scope identifiers return not found.

Change-impact analysis is the third analysis type in the existing `/analyses` Run lifecycle. The author supplies an explicit proposed change, target kind, and optional target identifier. The immutable input binds the current project, saved draft revision, source revision, Memory version, Author Context version and digest, and alias version and digest. The bounded retrieval payload contains only supplied character records and aliases, selected plans, confirmed Memory, saved draft claims, written SourceSpans, chapters, and world records.

The result may identify affected chapters, characters, world records, Memory records, and plans. Every impact item must cite one to five resolvable supplied records. A response with no impact items is normalized to the deterministic conclusion `当前证据不足以支持影响结论。`; the Provider's unsupported summary is discarded. An item with empty, malformed, or unresolvable Evidence fails closed and stores no result. The schema has no replacement-prose field, proposal-save field, or mutation instruction. Failure, timeout, cancellation, invalid JSON, unresolved Evidence, or stale retry writes no partial result.

Desktop character archives expose alias maintenance, one explicit proposed-change field, current result, Evidence links, status, and Run history. The current surface prefers the latest Run whose proposal targets the selected character; other-character Runs stay in history with their target name, ID, and proposed change. While any project change-impact Run is active, another create action is disabled. Every Run shows its original draft revision, source revision, Story Memory version, Author Context version, alias version, and retrieval method even after it becomes stale.

Evidence paths use real product routes and stable anchors: SourceSpans use `sources#span-{id}`, characters and aliases use the character route plus an explicit character query and `character-{id}` or `alias-{id}`, world records use `world-{id}`, Memory uses `memory-{id}`, plans use `plan-{id}`, and draft claims return to `workspace#draft-source`. The destination selects the requested character or world record and visibly targets the referenced record. At 390 px the same records, bindings, proposals, and Evidence remain readable while add, edit, archive, create, retry, and cancel controls are absent.
