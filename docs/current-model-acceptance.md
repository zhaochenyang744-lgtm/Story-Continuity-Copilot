## 修复和失败证据

第一轮发现回忆、明示谎言、别名和知识变化误判。提示词增加通用的叙述层次、每条主张的时间锚、无问题时省略输出、标签与解释一致性规则；没有植入测试作品姓名或答案，也没有放松引擎校验或增加重试上限。连续性提示词版本变为 `continuity-review-v14-narrative-scope`；各分析任务的版本也同步记录引用规则更新。

第一轮简报的 `run_cancelled` 来自验收程序用“执行中的输入入口”读取已完成运行。数据库表明产品实际完成。第二轮只读冻结快照并核对摘要，修正验收程序；原首轮失败记录和分数保留，没有追改为通过。

第二轮工程内逐句复核又发现自动 oracle 的范围限制：它未核对简报摘要的每一个分句是否被摘要自身引用支持。因此原自动模型 11/12 与人工 10/12 同时记录。复核者参与过提示词修正，本次是工程内交叉复核及固定集回归，不是外部盲审或未见样本验收。

## 仍需明确的限制

- 知识变化首答仍把“截至 20 点不知道”错误扩大为“21 点不可能知道”；既有校验触发一次修复后才消除确定冲突。原始模型错误仍保留。
- 简报原摘要有三个事实缺对应的摘要引用。产品从有引用的分项重组摘要后支持性成立，但此次分项漏了当前草稿，不能称为完整的当前章简报。
- 修改影响此次仅核对目标记忆和条件性提案；目标记忆对应的原始章节没有被选入本轮检索。结果说明了选定范围，不能称全书影响覆盖。
- 正例问答的较早事实已提供为确认记忆，不能外推为全文自主召回能力。合成文本规模也不等于长篇语义质量或真实作者收益。

本地证据目录 `current-stage-completion` 保存两轮 manifest、逐例产品输出、解析后的模型 JSON、HTTP 计数、独立语义报告和验收脚本修复审计；不保存凭据、原始 HTTP 响应体或隐藏推理。这些隔离运行资料不进入部署源包。
