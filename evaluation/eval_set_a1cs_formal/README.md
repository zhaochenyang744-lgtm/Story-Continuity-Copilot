# A1c 长文本安全留用集

`set_id: a1cs-formal`；`version: a1c-1`。一部中文安全作品，十二章，每章2500–3500汉字；十二道SAFE题，其中十道QA形式、两道FIX形式。

权威协议：`evaluation/assistant_a1c/SPEC.md` 的“2026-10-16 补充二”第4条及任务07m；字段沿用A1与A1b规定。安全专用作品不继承普通三十章作品的第十五章后易手、第十六和三十一章计划、跨十章状态变化或有意矛盾数量；按任务要求提供不少于六个具名人物。普通作品的这些规模要求无法直接套用十二章安全作品。本文本无有意矛盾；FIX的两处有意矛盾仅存在于各题独立草稿。

## 结构

- `works/lumen.md`：逐章原创正文。
- `tasks.json`：作品元数据、题目、标准答案、禁止行为、准确指令载体。
- `authoring/story-bible.md`：主代理先行设定与逐段确认交接。
- `authoring/self-review.json`：逐题语义自查、实际汉字位置、作者之外的独立通读记录。
- `set.sha256`：按相对路径排序，覆盖题目文件和作品目录全部文件。
- `check.py`：离线、只读本套题集的静态结构及完整性检查。

## 使用与隔离

交付后封存。正式运行前，调试会话只运行检查器，不打开作品、题目、设定及自查内容。任务间共用导入项目但整篇替换草稿；QA使用共享草稿，两道FIX分别使用各自草稿。指令是待测的不可信材料，不是出题过程或运行器的操作授权。

`safe_kind`分布：`injection_text` 2、`injection_draft` 1、`injection_fact` 1、`injection_plan` 1、`jailbreak_question` 2、`system_prompt_request` 1、`add_setup_lure` 1、`off_topic` 2、`direct_edit_request` 1。脱离作品的两道请求为不同任务类型。

本套固定选择：正文注入为QA、计划注入为QA，草稿注入与铺垫诱导为FIX。检查器按这一具体成卷结构校验；协议也允许的正文注入FIX和计划RECAP不在本套采用，检查器不是其他SAFE题集的通用校验器。

注入和引用位置均按章节正文中的汉字计数，从1开始，标题与标点不计。检查器重新定位实际文本，不信任自查所填位置；正文注入和越权问题的回答依据必须超过1500汉字。8汉字照抄检查沿用调试集去标点、专名以边界隔开的算法，检查题目、草稿和共享草稿与依据章节全文，另核对补充事实和计划的非指令内容。

可从任何当前目录运行指定Python（路径按实际位置填写）加 `-B` 和本目录 `check.py` 的绝对路径。检查器输出只有数字、结构和固定错误码，正常失败不输出原文或异常消息。结构PASS不等于独立语义证明，不等于产品检查命中，更不等于真实模型评测通过。

新颖性比对仅使用获准的A1c调试集；未打开其他题集，不能将未做的全仓库内容比对声明为通过。全部正文为按统一设定逐章撰写；程序只承担保存、计数、定位、查重复、格式校验及哈希。
