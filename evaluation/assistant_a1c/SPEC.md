# A1c 助手评测：真实章节长度

状态：**2026-10-16 用户批准**（作为 v1.8 上线门槛；规模取"中等"）。门槛写在同目录 `thresholds.py`，和本说明一起提交，作为预先登记。登记时 A1c 的两套题还没有写；A1 + A1b 的正式评测正在进行，A1c 不改它们的任何规则。

## 为什么要 A1c

A1、A1b 的作品每章只有 450–700 字，"100 章长篇"全书约 4.7 万字。真实作者的一章通常有 2,000–5,000 字。章节变长以后，助手每次最多读 2,000 字，要分几次往后读；搜索命中更多、噪声更大；花费和耗时离上限更近。A1c 专门检验这些。

**v1.8 通过 = A1 + A1b 正式评测通过，并且 A1c 正式评测通过。**

## 1. 两套题

| 题集 | 作品 | 题数 |
|---|---|---|
| 调试集 `eval_set_a1c_dev` | 1 部中文，30 章，每章 2,500–3,500 字（全书约 9 万字） | 15：QA 9、RECAP 2、FIX 2、追问 2 |
| 正式集 `eval_set_a1c_formal` | 2 部中文，各 30 章，每章 2,500–3,500 字（合计约 18 万字） | 30（每部 15）：QA 18、RECAP 4、FIX 4、追问 4 |

调试集谁都可以读；正式集交付后封存、算 SHA-256，正式运行前 Claude 和调试会话都不读它的内容，只跑结构检查器。两套作品、人物、地名、物件全部不同，也和此前所有题集不同。

## 2. 作品

沿用 A1 SPEC 第 3 节的写法、照抄规则（中文连续 8 字，专名按 `names` 豁免）和 A1b SPEC 的字段约定。另外：

| 项目 | 调试集（1 部 30 章） | 正式集（2 部，每部 30 章；下列要求每部各自满足） |
|---|---|---|
| 每章长度 | 2,500–3,500 汉字（不含标题、标点） | 同左 |
| 具名人物 | ≥8，≥3 人有别名 | 同左 |
| 易手的物件 | ≥3，≥1 件在第 15 章后换手 | 同左 |
| 状态变化 | ≥4，≥2 处前后相隔 ≥10 章 | 同左 |
| 线索 | ≥4（≥1 已收、≥1 到结尾未收） | 同左 |
| 有意的前后不一致 | 2–3 处 | 同左 |
| 计划 | 第 16、31 章 | 同左 |
| 共享草稿 | 第 31 章开头，800–1,200 字，含 1 条只在草稿里出现的事实 | 同左 |

**章内位置是 A1c 的重点：**
- 每章都要像真实章节一样有起伏：几个场景、对话、过渡，不是一个场景拉长。
- 考点句**至少一半落在所在章的第 1,500 字之后**（按章内汉字位置计），其中至少三分之一落在第 2,500 字之后。自查时写明每个考点句在章内的字位置。
- 同一章里放和考点相近的干扰内容（同一物件的其他描写、同一人物的其他动作），让"只读开头"或"只看第一条搜索命中"答不对。

## 3. 题目

字段同 A1 SPEC 第 4 节和 A1b SPEC 3.2（追问）。分布：

| | 调试集 | 正式集（两部合计，每部各一半） |
|---|---:|---:|
| `answerable_single` | 2 | 4 |
| `answerable_multi`（依据章相隔 ≥10 章） | 3 | 6 |
| `not_in_text` | 2 | 4 |
| `conflicting` | 2 | 4 |
| RECAP | 2（k=15、k=30） | 4（每部 k=15、k=30） |
| FIX | 2 | 4（至少 3 类） |
| 追问 | 2 | 4 |

- 每道有答案的 QA、每道追问（针对追问本身）加 `evidence_quotes`：依据句在正文里的原样片段（每句 10–60 字，和 `evidence_chapters` 一一对应），只给检查器和复核用，不给模型。再加 `deep: true/false`：任一依据句在所在章第 1,500 字之后即为 true。正式集里 `deep: true` 的有答案题和追问合计至少 12 道（每部至少 5 道）。
- QA 至少一半换说法问，至少 3 题带 `selection`（选中草稿里一段**句子**，不是只选一个人名）。
- RECAP 的 `draft_opening` 用 2–4 句；`must_mention` 里至少 1 条的依据在上一章第 1,500 字之后（上一章停在哪，本来就在章末）。

## 4. 运行方式

- 走真实用户路径，用生产配置（deepseek-flash、8 步、¥0.3、90 秒）；每次读章节最多 2,000 字，助手要自己分次往后读。
- **正式评测连跑 3 遍**，3 遍之间不改任何东西；作品只准备一次，3 遍共用。基础设施重试同 A1。
- 调试最多 3 轮，只用 A1c 调试集；正式集内容在正式运行前不读。
- 评分、复核（判错全部、判对按种子 20261016 抽 20%）、复核推翻改变门槛时由用户定，都同 A1。
- A1c 和 A1/A1b 的正式评测分开运行；A1c 的调试和改动不得影响已经跑完的 A1/A1b 结果的有效性。如果为 A1c 改了助手的代码或提示词，A1/A1b 正式评测必须用改后的版本**换新题集重跑**才算数（用备用题集）。

## 5. 门槛

见 `thresholds.py`，摘要：

| 指标 | 门槛 |
|---|---|
| QA 有答案题答对率（3 遍合并） | ≥ 0.8 |
| 其中依据在章内深处（`deep: true`，含追问）的答对率 | ≥ 0.75 |
| QA 找不到题答对率 | ≥ 0.8 |
| QA 前后不一致题答对率 | ≥ 2/3 |
| 追问答对率 | ≥ 0.75 |
| 引用支持率（QA、追问、RECAP） | ≥ 0.9 |
| RECAP 必提要点召回 | ≥ 0.7 |
| RECAP 不该出现的内容出现次数（3 遍合计） | ≤ 3 |
| FIX 成功率 | ≥ 0.75 |
| pass^3（3 遍都对的题占比） | ≥ 0.7 |
| 每任务 8 步、¥0.3 以内 | = 1.0 |
| 助手任务耗时 p90 | ≤ 45 秒 |
| 因到达上限而强制收尾的比例 | ≤ 0.2 |
| 内部标识泄露 | = 0 |

只报告：每任务花费和步数的分布；每任务读了多少字；首次交稿通过率；每遍各自的值。

## 6. 检查器

同 A1 SPEC 第 8 节，另查：章数、每章字数在范围内；题目分布；`deep` 标注与依据句位置一致（检查器按依据句在章内的实际位置核对）；正式集 `deep: true` 至少 12 道、每部至少 5 道；`set.sha256` 覆盖 `tasks.json` 和 `works/` 全部文件。

## 2026-10-16 补充三（用户批准；A1c 调试集、正式集、安全题集都还没有运行）

9. **引用判定里的指代。** 开发题第 1 轮（`a1cx-dev-r1-p5`，用的是已经用过的长文本作品）中，引用误判的大头是这一类：原文写"少年点头道别"，助手写"殷明德点头道别"，评分模型以原文没有出现"殷明德"为由判为没有依据。长篇小说常用"少年""她""老人"等称呼人物，这样判会让引用支持率系统性偏低。现在给 `citation_support` 和 `recap_summary_support` 两个评分问题各加一句判定说明（英文原文登记在 `thresholds.py` 的 `PRE_REGISTRATION["judging"]["citation_referents"]`），大意是：原文只用代词、称呼或身份指代某人某物时，句子写出名字算有依据，前提是原文没有在那个位置写出别的名字；把动作或事实安到原文点名的另一个人身上，仍然没有依据。评分问题本身的措辞不变，门槛数值不变。

   同日补记（仍在任何 A1c 运行之前）：开发题第 2 轮显示，这句说明只放在评分问题后面时，会被"句子有任何一处超出原文就算没有依据"压过去。现在把同样的意思（并附一个"少年点头道别"支持"殷明德点头道别"的例子）也写进这两个问题"supported / unsupported"两个取值的含义里。用第 2 轮被判没有依据的 18 条引用试判，10 条改判为有依据，其余仍判没有依据（其中包括句子确实超出原文的几条）。
