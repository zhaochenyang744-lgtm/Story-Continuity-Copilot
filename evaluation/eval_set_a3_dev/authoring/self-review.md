# A3 调试集主作者自查

本文在独立全文初审完成后、最终检查器运行前编写。独立全文审读见 `independent-reading.md` 与 `independent-review.json`；路由另做仅接触打乱后的 input/context 的盲判。结构核验不能代替语义复核，也不表示模型或产品质量通过。

## 正文、材料与设计边界

原创作品《把空拍留在桌上》为当代大学校园声音编辑部筹备毕业特刊的连续叙事。30章共89,849纯汉字，不计标题；每章2,851—3,119字。共享第31章草稿738纯汉字，逐字放入 tasks.json，不进入30章正文。11名人物中3名有别名；任务登记24项专名，书名另作旧集扫描。

主作者按章写作、逐波交接状态。唯一正文为 works/w01.md；分章工作副本组装后删除。第8章的回顾锚点统一为“第一次正式试听”，区别第2章普通试音；独立全文审读后，第27章“当年那两个停顿”改为“当时那两个停顿”，仅纠正当前学期措辞。两项修订均不消除或扩大设计考点。原始组装与后审哈希留在 assembly.json。

三项追踪对象各5个状态：
- 苔点录音机：唐1→许5→陆10→庄16→唐28；同一原铭牌在10/22章分别六三九、九三六，一处矛盾。
- 折翼监听耳机：陆2→谢7→闻12→方18→陆30；同一未换原装左耳罩在7/24章分别方框、圆环且从未方框，一处矛盾。
- 匿名嘉宾真名知情范围：唐3→唐许及本人8→加陆14→加庄20→全编辑部29；8/26章对同次首次正式试听的穷尽知情名单不能共真，20章支持这同一矛盾，不重复计数。内部许可不等于公开署名或未来具名采访。

三对象首末跨度为27、28、26章。第三项是描述性追踪标签，不是新增专名。双格样本盘另有9→15→21章交接，是普通物件连续性要求，不另算第四项追踪。

两处决策点各无正文过渡：11/13章同一首次正式报名页题名两说；23/25章同一次首次公开播放的最初预约周六/周日两说。均不与三处追踪矛盾重复计数。第30章只写试听当天，未替作者选边。

初始事实30条，故意过时1—3（碰头时段、试听地点、采编分工），真实缺漏6项。初始伏笔9条，状态为 planted=4、developing=4、resolved=1。正文已收而材料未标1/2/3，正文明确放弃4且材料仍developing，仍开放5/6/7/8，9已正确resolved。开放线没有“以后不写”这类放弃语句；广播开场者身份仍未知，但19章明确不要再找，不能当成回收。

诱饵事实4/5/6分别把“大三”换成“读第三年”、设备借还管理换成领还登记、导师只建议无投票权换个说法。均已被资料覆盖，不重复新增。谢的领还管理不等于外借前电量核验；庄的报名与录音分离不等于亲自确认文字授权。六项缺漏按独立主谓槽位核实。最初安排或初次事件记录若未声称“当前仍然”，后文时间推进不机械算成过时。

## 冻结与复核口径

所有正文、材料、自查引句逐字唯一性由离线脚本辅助核验；正文没有40汉字以上完全相同的整段。request/input/after_points按专名作为边界后去标点，核连续8汉字照抄；共享草稿额外做同类检查。选区仅出现在writing且取共享草稿完整句，不能用句中短语。

旧集清单先排除三处禁读目录再遍历，仅读取允许集README及新颖性所需任务/材料等文件。新颖性快照冻结27份tasks.json、663条按来源去重的规范化旧输入，记录715个旧登记专名；新集24专名及书名另对460份允许旧MD/JSON扫描。检查器只读本集快照并固定快照SHA，不重新打开旧集。最终补充审计再核允许旧任务清单和内容未漂移，并计算全部比较对的真实最高相似度；检查器的novelty_max_tested_similarity仅是长度上界达到0.8候选中的最大值，报告不可把它冒充全量最大值。

独立全文审读的第27章措辞建议已采纳关闭；独立18题审读指出fact2的改写应保留“正式”限定，已将“往后试听只用苇屏室”收紧为“往后正式试听只用苇屏室”，未扩大正文权限。盲判首轮10/10与金标一致，无改题追平；08题的指代歧义按资料页无选区的上下文说明保留。完整原始盲判输入、顺序、逐条判定与理由均已记录。

task-intents的操作类型与对象索引在出题前冻结并由检查器固定摘要；它独立于expected_actions枚举范围内全集，避免删一卡再重算manifest仍通过。两条作者答复还需只含一种明确a/b选择，不能双选。独立静态复核同时确认这套真实数据的4/3/2伏笔卡全集、叙述决策空卡及正文哈希负测均有对应检查。

最终冻结次序为：独立全文初审→主作者出题→独立18题语义复核与路由盲判→关闭发现并更新正文/任务/自查绑定→四数据文件排序SHA清单→最终检查器→四个独立坏副本负向测试→补充审计。任何后续语义改动都应回到语义复核并更新绑定及清单。最终结果以authoring中的实际JSON证据与交付报告为准。
