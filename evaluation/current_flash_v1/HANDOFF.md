### Specific bad cases for controller review

1. **V8 retrieval and decision chain:** `v8-dusk-viaduct-conflict-relationship` expected chapters 1 and 2, yet the first actual model request included chapters 1, 5 and 7. All eight conflict cases lacked their complete expected evidence in the model request. The historical top five metric continued to read true for all 24, so it overstates effective prompt coverage under current `ContinuityEngine._selected_evidence` selection. The model also returned empty issues for most V8 cases. Both effects require separate diagnosis before blaming a model alone.
2. **G02 three-sentence brief:** the model's three draft items each cite and accurately restate their own sentence. Its first summary additionally asserts confirmed memory facts while `summary_sources` lists only the three draft claims. The product replaces that summary deterministically; inspect the saved [case](runs/flash-v1-20260926-01/cases/35-g02-three-sentences.json) before treating first-model summary support as correct.
3. **G02 299-character sentence:** the model and final product item state the sentence's tail, “最后把银钥匙交给陈澈并得知弟弟还活着”, but the item's own `draft_claim` citation contains only the first 240 characters and omits that tail. The full saved draft excerpt gave the model the tail; this is an **item citation support gap**, not proof that the fact was invented. Product correctly labels overall draft coverage `partial/draft_claim_truncated` but retains the item. [Case](runs/flash-v1-20260926-01/cases/36-g02-long-sentence.json).
4. **G03 short and other-chapter:** first model JSON adds the current draft ID as a `chapter` impact target. The product rejects both with `evidence_unresolvable`; HTTP and parsed outputs are preserved. [Short](runs/flash-v1-20260926-01/cases/39-g03-short-target.json), [other chapter](runs/flash-v1-20260926-01/cases/42-g03-other-chapter.json).
5. **G03 deep and absent:** the 1510-character deep source's target fact appears in the 502-character supplied excerpt; the direct memory and chapter impact survives with own source citations. The model also adds an unrelated character item, so open-ended impact semantics still need manual review. In the absent case the source is `unlocated`; the model emits impacts, and the product correctly strips them to `insufficient` with no items. [Deep](runs/flash-v1-20260926-01/cases/40-g03-deep-target.json), [absent](runs/flash-v1-20260926-01/cases/41-g03-fact-absent.json).

The G02 body-limit case disclosed `draft_claim_uncovered`, `draft_claim_unselected` and `draft_body_truncated`; the identical-text case cited both matching claim IDs and ended covered. Their nonliteral open-ended item semantics remain for independent human checking. The G03 negative case made one real model call despite the pre-run plan allowing zero; actual dispatch count is used throughout.
