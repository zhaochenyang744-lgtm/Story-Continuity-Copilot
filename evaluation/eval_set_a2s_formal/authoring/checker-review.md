# 两个 A2 检查器首轮独立审查

审查者未参与两个 check.py 的编写。本轮只读两个检查器、已读取的任务单和登记 SPEC，以及 authoring JSON 的字段类型/形状；未读取正式集 tasks.json，未运行整套检查器、产品、评测或模型接口，未改动检查器或作品。这里只审结构实现，不声称完成正式题目语义复核。

首轮两份检查器各470行，除 SAFETY 常量外完全一致。下列行号针对首轮快照；精确 SHA-256、9项纯函数/逻辑探针及 authoring 结构快照见 `checker-review.json`。主代理在收到首轮发现后开始修订；本文件保留原始发现，不将未复核修订写成已修复。

## 首轮发现

### CR01 / P1：失败输出会透出任意枚举值

位置：159行附近的 states 及205行附近的 foreshadow_states；388–422行的 primary/no/routes/suites；436–444行的安全集位置、用法和动作计数；460–465行输出。

need() 记录错误后继续统计，Counter 的原始字符串键随后被 dict() 放进结果。若把一个 status、expected_route、no_action_type、动作kind或注入location.kind改成任意非枚举字符串，这段字符串仍可能原样出现在 FAIL JSON 中。外层 except 只处理抛异常的情况，不能阻止合法字符串经过失败路径。此问题不需要真实内容即可证明：纯逻辑探针确认任意标记会保留在 Counter 的序列化结果中。

要求：输出计数只允许固定枚举键，未知值合计入固定的 invalid 计数；错误只能使用固定代码、合法题号和数字。补负向输出探针，确认标记不存在于 stdout。

### CR02 / P2：self-review 的章字段可缺失或被另一类字段覆盖

位置：171–198行附近，尤其 `entry.get('changed_chapter', entry.get('chapter'))`；262–265行的动作证据绑定。

三个数组的条目没有分类型锁定必需字段。missing_facts 可以不含 chapter，改带 changed_chapter，仍被 quote() 和后面的 proof 绑定接受；resolved_unmarked 若同时带两个章字段，quote() 优先检查 changed_chapter，状态/时序却检查 chapter，导致“所写章节中有原句”的检查不再对应同一个字段。

要求：三类 entry 各自锁定精确字段、各自的整数章字段，然后只把该字段传给 quote()。别名等扩展条目也应明确 schema，避免同类覆盖。

### CR03 / P2：also_acceptable 的题数按非空值计，未按字段存在计

位置：325–326、401–402行。

单题允许空列表，但总数使用 `sum(bool(t.get('also_acceptable')) ...)`。至少三道题都带空列表时，统计仍为0，绕过“每部最多2道带该字段”。逻辑探针记录3个带字段项而当前计数为0。

要求：按 `'also_acceptable' in t` 计数；若希望字段出现时必须有一个候选，则再单独固定这一写法。

### CR04 / P2：照抄库包含标题，并跨章拼接正文

位置：149行附近的 `references[wk] = grams(source, names)`。

grams() 删除所有非汉字后从整个 Markdown 取窗口，标题会参加比对，章末、下一章标题和下一章正文也会被拼成不存在于任何一章正文的连续8字。因此可能把合规题面误报为正文照抄。合成纯函数探针以两个不足8字的章节正文验证：正文窗口并集为0，整文件窗口仍非0。

要求：以每章 body 单独取 grams，再求并集；不使用整个含标题源文件取窗口。

### CR05 / P2：允许的 support FIX 分支实际上无法通过

位置：209–218行题号正则与固定总题数，276–299行公共字段，以及376–381行 FIX 分支。

规则允许 route.fix_issue 引用额外的 support:true FIX，支持题不运行、不计分。但题号正则没有 fix，且所有 tasks（包括支持题）都必须合计56；主任务本身已有56道，增加1道支持题即超总数。FIX 分支虽然存在，前置规则已使其无法通过。另需明确支持题究竟按 A1c FIX 公共字段还是 A2 主任务字段检查，避免又被 request/context/why 的要求阻断。

要求：总题数和56道分布只数主任务；支持题另计；题号允许支持 FIX；以登记的支持题 schema 检查其字段及同作品 issue_from。若本套不用 fix_issue，当前数据可以避开此路径，但不能称该可选路径已完整实现。

### CR06 / P2：selection 只要含标点便可通过

位置：289–292行。

当前仅要求是共享草稿子串且包含一个终止标点，未验证从句首开始、在句末结束。因此从半句截起，或在句号后再截半句，仍能通过，不能保证“原样的一句或几句”。

要求：在保留逐字子串与80字符上限的同时核对完整句边界；终止符取值按任务单“带句号”及登记说明固定。勿把仅包含标点等同完整句。

## CR07 / P3：新颖性快照的完整性证据较弱

位置：220–224、453–454行。

只读本套的实现通过本地 novelty-reference.json 复用旧输入，符合不进入旧题集的运行边界。但 source_hashes 只要求是非空字典，没有验证值为SHA-256、来源清单与输入集合的绑定，也未将快照文件加入独立审读的绑定清单。names_overlap 为0是作者审计声明，检查器只把候选专名列表绑定回该声明。

这不是本次快照已经缺项的结论；本轮没有读取旧题验证完整来源。建议固定快照 SHA-256 与来源清单/数量，并由主代理在出题阶段审计、冻结。检查器无需因此重新读取旧题集。

## 已覆盖的结构与边界

- 目录和清单：按自身 __file__ 定位；预期数据文件路径固定；清单按路径排序、逐文件核SHA-256；作品和资料目录的额外文件会被拒绝；路径读取限定在本套。
- 正文和草稿：分别核章数、每章汉字数、共享草稿章号及汉字数；数字章号与完整章标题有明确转换路径。
- 起始资料：事实/伏笔数量、字段、枚举、长度、序号范围、状态和已收章时序均有检查；缺事实对象键排重、目标数组排重及未收线数量有检查。
- 动作和安全：三类合法动作目标绑定到本套self-review；原句逐字检查、章节对齐；主要动作、双动作、改写标志和模糊标志分布已计；注入四类位置均到具体载体核对，正文位置重算；允许动作与注入目标有重叠检查。
- 正式路由：六种用法、主分布、选择上下文、同句异上下文组和人工语义标签均有检查；独立盲判摘要与审读覆盖/数据哈希有入口。
- 程序边界：只导入标准库，无网络、模型、产品或评测导入，无写文件代码。正常 main 输出为一行JSON且失败返回非零。任意cwd能力由路径实现支持，实际两种运行命令仍须主代理在最终数据齐备后验证。

## 必须区分的限制

- 本轮是代码审查和纯函数逻辑探针，不是最终两套数据 PASS；5类任务单负向测试仍待完整数据后在临时副本运行。
- 口语、模糊、问句长得像改资料、载荷与请求的语义关联、全部起始事实是否真实等不能仅凭字段声明证明，仍需独立正文/题目复核。
- 当前代码还固定每题最多2条动作、至少含与self-review完全相同的证据摘录，并额外要求若干authoring文件。若保留，应在README明确为本套成卷的作者选择，不冒称登记规则规定了一般上限或完全相同摘录。
- 源码改动后须以新SHA快照复核，本报告的首轮行号和发现不能自行视作修订版本的最终状态。
