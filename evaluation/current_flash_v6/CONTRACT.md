# Current Flash V6 contract and offline control plan

Status: pre-implementation design, 2026-09-27. This is a new seen-development version. V5 files, gold, raw responses, scores and frozen manifests remain historical evidence. No Provider dispatch is part of this phase.

## Main proposition and source roles

The review target is the story-fact proposition P in the current claim. A phrase such as “the register establishes P” adds a source-attribution assertion but does not make absent register detail a proof of not-P. If the register explicitly omits the required detail, report `insufficient_evidence`: say the attribution is unsupported and P remains unknown. Do not create a separate attribution issue. This rule is declared before V6 scoring for the ambiguous V5 cases 15 and 24.

`evidence.relation` is always relative to P. `contradicts` means the cited text supplies a fact incompatible with P after entity, time and rule premises are bound. `context` supplies an identity, governing rule, time/scope premise, or relevant optional context; it does not itself assert not-P. `supports` means the cited text supports P, and may not be relabeled as a contradiction. `evidence.sufficiency` means that the cited text is complete enough **for its declared local role**. Sufficiency of a confirmed conflict is determined over the **whole cited set**; an auxiliary `sufficient` flag alone does not prove the conflict.

A `confirmed_conflict` requires at least one selected, directly contradictory and locally sufficient citation, every necessary identity/rule/time premise in the same issue, and a coherent explanation of how the set proves that P cannot coexist with the sources. Selected ID, chapter, revision and Memory source-span binding remain hard checks. The product validator can verify the structural part: a direct contradiction exists, no `supports` is misused as contradiction, citations are selected and bound, chain matches the citation set, and time/rule anchors meet existing checks. Natural-language necessity, relevance and complete proof remain independent semantic controls. It would be false to claim that one `contradicts` plus arbitrary context is generally sufficient.

The prompt should omit optional context unless it clarifies a specific proof step. If context is cited, the explanation/reasoning must identify its role using the existing `evidence_chain` and its text, without adding a broad new issue schema. An unselected source fails regardless of narrative plausibility. A source that supports P must not be silently changed to `contradicts`; the raw and final layers remain separately visible. Existing valid `state_change` and compatible new events are preserved.

## Coverage of empty results

The model-facing V6 response will add a small `claim_verdicts` list: exactly one entry per supplied claim, containing its bound claim ID, `conflict`, `insufficient_evidence`, or `no_issue`, and a short basis. Every emitted issue must match its verdict. A `no_issue` entry must state whether the claim is directly supported, a compatible change/new fact, or an attributed utterance rather than asserting an unsupported evidence-dependent link. A repair that removes an issue must give an explicit new `no_issue` basis. A missing, duplicate, contradictory or blank verdict is a contract failure eligible for the existing one bounded repair, never silently interpreted as no conflict.

This ledger makes omission visible and checkable, but cannot prove the model chose the correct semantic verdict. In particular, a wrong `no_issue` explanation can still miss a real evidence gap. V6 semantic controls and later real-answer review must catch that; no case ID, gold class, or fixed expected answer enters product code. Ordinary compatible new events remain valid `no_issue` without an old source warrant. The provider-facing ledger is stripped before the existing Issue persistence/API surface; V6 evaluation journals save the raw ledger. No database migration or author-facing API field is planned for this bounded repair. Existing legacy/test providers retain their old response path; the real V6 continuity provider requires the new ledger. If this compatibility route proves unsafe in offline tests, stop before Provider and revise the design explicitly.

## Expected changed files and controls

- `backend/app/provider.py`: new continuity prompt version, precise evidence roles, story-fact attribution, and per-claim verdict schema/repair wording. Context-brief prompt remains unchanged.
- `backend/app/engine.py`: version-gated verdict validation, mixed-role confirmed-conflict structural rule, related repair diagnostics and unchanged bounded transport/contract limits. The standalone `WritingAnalysisEngine` and G02 citation renderer remain untouched.
- `backend/tests/test_v6_continuity_contract.py`: minimal positive and negative controls: necessary rule/identity premise plus direct contradiction; all-supports; unsupported extra or unrelated context; missing premise; unselected/wrong chapter/Memory; unknown/different time; insufficient versus explained no-issue; repair removal; compatible new event; legal state change.
- `evaluation/current_flash_v6/`: versioned scoring and input lineage, one offline capture per fixed case, durable runner/journal/freezer, frozen case and control manifest, and offline handoff. V3/V2 scorer modules remain byte-identical; V6 scoring must distinguish raw, repair and final, and score mixed roles by the new declared policy rather than silently delegating the V5 all-contradicts rule.
- Because `provider.py` and `engine.py` are shared, replay the six saved G02 requests and first answers offline through the current analysis validator, compare final citation-bound products, and verify G02 prompt/schema/parameters are unchanged. This is a preservation check, not a new real-model success claim.

## Control interpretation

The 12 independently declared semantic controls and eight existing no-conflict cases are the preflight floor. A machine structural pass never substitutes for their semantic assessment. In V6, a mixed proof is accepted only when its entire selected cited set actually grounds the entity/rule/time link and incompatibility. Unrelated context is a semantic failure even if its IDs are structurally valid; an obviously wrong binding is a structural failure. Empty issues with a missing or contradictory verdict fail; a supported new compatible fact can retain an empty issue list. Old V5 outputs may be replayed for contract-adaptation diagnostics only, never called a new model improvement.
