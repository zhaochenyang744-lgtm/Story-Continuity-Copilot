The first temporal addendum described a theoretically applicable timeless readiness rule for the new capsule control. The accepted API input-v2 fixture mirrors R1 as a `dynamic_state/status` Memory, while the product's `timeless_rule` validator requires a cited `static_canon/rule` Memory. Therefore the new control accepts only `explicit_overlap` through R2 in this run. The two inherited old joint-rule cases retain both time forms because their current inputs contain qualifying rule Memory. This narrows scoring to the actual frozen business input and does not change that input or product rules.

The companion-record control has `category_policy=manual_variant` and candidates `location_action` or `relationship`. V6 scoring requires membership in that set; a null default category is not a wildcard. The category remains pending human adjudication when one of those declared variants is structurally valid.
