## Cases and interpretation frozen before dispatch

Eight exposed development regressions: G02 four saved draft bodies exactly match v1; G03 four named modes use a new deterministic, evaluation-only two-chapter project. G02 therefore permits a comparison on draft text under the same tracked product version, while the business request must still be compared explicitly: API identities and selected context may vary. G03 changes the fixture and is **not** a strict same-input score improvement. No unseen/blind claims or aggregate open-ended model accuracy are permitted.

The G03 base has fixed logical target Memory `fixture-memory-flash_v2_target-1`, `dynamic_state / 星钥 / holder / 星钥始终由乔霁保管。`, sourced from chapter 1 span 1. Chapter 2 span 2 is a separate source. The short/deep cases contain the target fact in chapter 1; deep puts it late in a 1510-character body. The absent case deliberately leaves the confirmed Memory and chapter source inconsistent: a Memory/proposal comparison may be conditional, but a determinate claim about missing chapter prose is unsupported. The other-chapter case supplies a relevant chapter 2 account of Shen briefly touching and returning the key, and pre-dispatch validation must prove both chapters and the interference span actually enter the model's business request. Chapter impact on either chapter needs that chapter's own span. The draft is empty in this fixture, so a fabricated draft chapter target remains invalid.

G02 evaluation checks each first summary against its own `summary_sources`, and every item against its own `sources`, then separately checks the final product summary/items. The long sentence's tail is known to be in the saved 299-character draft while the selected claim citation stops at 240; a partial coverage label does not make that item's own citation sufficient. For identical text, either matching draft-claim ID can cite that sentence, while extra attributes such as the compass's crescent crack need their own evidence. The body-limit input repeats one sentence and tests disclosure of selection/truncation, not ability to detect a novel fact beyond the limit. These are manual semantic checks with frozen expectations, not a single automatic accuracy percentage.

## Harness, accounting and stops

`run.py` stores the actual structured business `request` passed into each Provider call, including bindings, all layers, retrieval, proposal, output schema, and a hash before constructing the provider prompt. It also saves every parsed first/repair business JSON, product terminal result, source IDs and a per-case database in an ignored local artifacts directory until controller acceptance. The record excludes generated prompt text, HTTP headers/body, credential, hidden reasoning and SMTP. The deterministic case, corpus, runner/tests, relevant seed, fixture loader and product source bytes are frozen in `frozen-inputs.json`. A run ID and each output file are create only.

The 8 logical cases each run once. HTTP attempts can exceed 8 only through the current product's bounded retry/repair behavior. The model remains `deepseek-flash`, provider `deepseek`, base URL `https://api.deepseek.com`, JSON object mode, thinking disabled, temperature 0, product timeout 30 seconds and one transport retry. One `/models` preflight is separate. Authentication/model rejection stops immediately; two consecutive transport/service failures stop. Product schema/evidence failures remain quality outcomes and do not count toward that service stop. No user cost ceiling is added, no unlimited retries are permitted. Every dispatch counts.

Observer usage is complete only when `prompt_tokens`, `completion_tokens`, and `total_tokens` are nonnegative integers and total equals the sum of the first two. Missing/null/partial/negative/inconsistent values retain known fields but mark full usage unknown; complete totals are null if any dispatched attempt is incomplete. A price-sheet estimate is never reported as charged cost. The offline suite includes all these variants, observer behavior, no overwrite, stop semantics, all eight synthetic product paths, full business snapshot and pre-dispatch G03 source binding. Freeze and verify follow passing tests; only then execute the one new run ID.

The V1 V8 fixed regression missed all 8 conflicts and all 8 insufficient cases, but current model requests lacked full expected source evidence for all 8 conflicts. Independent review also found the old V8 `static_canon / fixture_anchor` memories cannot support the current strict `timeless_rule` contract in two relevant examples even with full evidence; the old three-class scorer can treat `possible_conflict` as `conflict`. Those historical labels and results remain unchanged. Future V8 adaptation needs a separate case version and plan, beyond v2.
