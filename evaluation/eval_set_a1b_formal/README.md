# A1b 正式集

任务 07a 的独立原创正式集，版本 `a1b-1`，集合 `a1b-formal`。调试集在本集开始写作前已经独立复核、检查通过并提交。

## 结构

- `l2`：100 章中文长篇，每章 400–700 汉字。
- `n`：12 章中文普通作品，每章 600–900 汉字。
- `s2`：8 章中文安全作品，每章 400–600 汉字。
- 长篇 QA 20：单章 5、多章 7、找不到 4、矛盾 4；RECAP 2，FIX 3。
- 追问 10：长篇 5、普通作品 5。
- SAFE 12：补充事实注入 2、计划 1、伏笔 1、标题 1、越狱问题 2、系统提示词 1、前文补设定诱导 1、离题 3。

## 写作与核对

主代理先写全书设定，明确人物与别名、全部易手章、状态前后章、线索埋设与收回章、有意矛盾。子代理每次只写获派的连续章节，并交接新人物、普通及具名物件、相对时间点。主代理接受并更新设定后才派下一段。每章正文均独立原创，工具只保存已经写定的文本或审计字数、重合与哈希，不通过程序、模板或句型替换生成正文。

全部题目与金标由主代理写定、合并并核对。`authoring/` 保留派写设定、逐段交接、手写题目片段、选定原句和独立审阅记录。已写题目片段中的数字章号仅用于编写阶段定位；正式 `tasks.json` 使用实际完整章名。第一问出处仅记入自查记录，不给任务格式添加额外字段。

每部全文写完后，由未参与写作的独立子代理通读正文和金标，专门区分无意矛盾、设定外事实与需保留的有意矛盾。发现、修复及复核记录合入 `authoring/self-review.json`。结构检查 PASS 只证明列明的离线检查，不代表模型质量或产品评测通过。

## 口径与歧义处理

- 正文长度只计算汉字，不含标题、标点、空白、阿拉伯数字；实际采用更严格的纯汉字口径。
- A1b 每套长篇只有 3 道 FIX，因此采用 3 个不同类别，不套用 A1 的 12 题至少 6 类要求；SAFE 中 FIX 类别单独统计。
- A1b 明确允许安全作品的补充事实、计划、伏笔及标题载荷，覆盖 A1 安全作品不带计划/伏笔的旧限制。
- 照抄按去标点空白后的连续 8 汉字判定，专名白名单作为断点；比较题目、第一问、追问、选中片段、共享草稿与各题完整依据章，并包含 FIX/RECAP 草稿。
- 不打开旧题集，因此没有声称完成与旧集的内容逐项比对；通过本轮独立设定与题材隔离，避免主动复用。
- 状态及易手前后必须分章合并；不能把现在的一条状态自动当作旧状态的证据。未知题仅问作品确有的人物物件及真正缺失的信息。
- 有意矛盾由专门人物或物件承载，FIX 与安全草稿避开它们；不得通过误记、历法或物件更换解释掉。

## 检查与封存

```powershell
..\story-continuity-copilot\.venv\Scripts\python.exe -B evaluation\eval_set_a1b_formal\check.py
```

检查器与调试集逐字节相同，以 `__file__` 定位本集，不读取其他题集，不输出作品内容。`--staged-dev` 只可用于调试集路径。`set.sha256` 精确覆盖 `tasks.json` 和 `works/` 下全部文件，按相对路径排序。交付文件均 UTF-8 无 BOM、LF。

交付封存后，正式运行前仅运行结构检查器，不再向调试方展示正文、人物、题目、答案或逐题依据。桌面交付报告只含本集的数字、结构、检查结果和哈希。
