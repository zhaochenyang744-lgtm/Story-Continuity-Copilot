## 结构

- **corpora（作品）**：建议 4–6 部短作品，每部 6–10 个“章节”。每个章节就是一段独立的原文记录，**不超过 300 字**（系统只把每条证据的前 500 个字符交给模型）。
  - `label`：英文小写短标签，作品内唯一，如 `gate_rule`、`watch_log`。
  - `is_rule`：这一段是不是**永久规则 / 世界设定**（任何时候都成立，如“红色徽章打不开北门”）。是则 `true`。
- **cases（题目）**：共 **36 题，冲突 / 无冲突 / 证据不足 各 12 题**。每题是作者草稿里的一句话（`draft`），让系统判断它和作品原文是否矛盾。
  - `expected_class`：`conflict`（与原文矛盾）、`no_conflict`（原文直接支持）、`insufficient_evidence`（原文缺了关键一环，无法判断）。
  - `evidence`：判断所需的章节标签列表。冲突题列出**共同构成矛盾的全部章节**；无冲突题列出直接支持它的章节；证据不足题列出最相关、但缺关键环节的章节。
  - `category`：**冲突题必填**，其他题填 `null`。取值见下表。
  - `designated_regression`：从冲突题中**恰好选 3 题**标 `true`，gate 要求这 3 题类别全对。建议分别覆盖：①谁做了某事（草稿说是甲做的，原文明确记录是乙做的，类别 `relationship`）；②带明确时间的固有属性（材质、颜色、尺寸，类别 `attribute`）；③规则本身就是唯一的反证（类别 `world_rule`）。

## 冲突题的硬性约束（否则答对也会被判无效）

确定冲突必须满足其一：

1. **同一明确时间**：草稿句和证据里的那个事实写着同一个明确时间，如都写“今天10点”“At 10:00 today”“第三天”。不要只写“当时”“后来”。
2. **永久规则**：证据里有一条 `is_rule: true` 的章节，且矛盾由这条规则推出。

## 类别（只对冲突题标注）

| 类别 | 含义 |
|---|---|
| `attribute` | 人或物的固有属性：材质、颜色、尺寸、数量等 |
| `object_state` | 物品可变的状态、持有人、放置位置（开/关、锁/未锁、就绪、在谁手里） |
| `relationship` | 谁做了/导致了/授权了某事，或人物之间的亲属、角色关系 |
| `character_knowledge` | 人物知道、相信、见过或听说了什么 |
| `timeline` | 事件的先后顺序 |
| `event_status` | 事件是否开始、完成、失败或仍未结束 |
| `location_action` | 人物在哪里，或在某地做了什么 |
| `world_rule` | 全局规则、机制或例外，且规则本身构成矛盾 |

请让 12 道冲突题覆盖全部 8 个类别。

## 建议

- 中英文都要有（如一半一半）；人名、地名、物品全新，不要沿用本项目已有评测里的故事。
- 每道题只考一个判断点；无冲突题可以在同一作品里放一些名字相近的干扰段落。
- 证据不足题要确实“缺一环”，而不是明显矛盾或明显支持。
